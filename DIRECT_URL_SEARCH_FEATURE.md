# Функція прямого переходу за URL в Vetale Search

## Опис функціональності

Коли користувач вводить у пошуковий рядок Vetale Search текст, що схожий на URL (наприклад, `google.com`, `github.com/user/repo`, `example.org`), система автоматично розпізнає це і додасть **спеціальний результат прямого переходу** на першу позицію, перед результатами з Wikipedia, WebArchive та інших джерел.

## Як це працює

### 1. Розпізнавання URL

Система використовує метод `NavigationBar.TryNormalizeUserUrl()` для перевірки, чи введений текст відповідає патерну URL:

- **Якщо текст містить пробіли** → це пошуковий запит, не URL
- **Якщо текст містить крапку і не містить пробілів** → це потенційний URL
- **Система автоматично додає `https://`**, якщо схема не вказана

**Приклади:**
- `google.com` → розпізнається як URL → `https://google.com`
- `github.com/microsoft/vscode` → розпізнається як URL → `https://github.com/microsoft/vscode`
- `vetale browser` → **НЕ** розпізнається як URL (містить пробіл)
- `wikipedia` → **НЕ** розпізнається як URL (немає крапки)

### 2. Відображення результату

Якщо введений текст розпізнано як URL, система створює спеціальний результат:

```
🌐 Перейти на google.com
Відкрити сайт: https://google.com
google.com
```

Цей результат:
- **Відображається першим** у списку результатів
- Має **спеціальний градієнтний стиль** (клас `result-item-direct`)
- Містить іконку 🌐 для візуальної ідентифікації
- Показує домен у заголовку
- Завантажує фавікон сайту

### 3. Стилізація

Прямий URL результат має унікальний стиль:
- **Градієнтний фон** (оранжевий → фіолетовий з прозорістю)
- **Товщий бордер** (3px замість 2px)
- **Більша тінь** для виділення
- **Більший padding** (20px замість 16px)
- **Більший border-radius** (16px замість 12px)

### 4. Взаємодія

Користувач може:
- Клікнути на результат → негайний перехід на сайт
- Переглянути фавікон сайту
- Побачити повний URL у описі

## Технічні деталі

### Файли, що були змінені:

1. **VetaleSearchResultsPage.axaml.cs**
   - Метод `RenderUnifiedResults()` - додає перевірку на URL
   - Метод `ExtractDomain()` - витягує домен з URL для заголовка
   - Метод `AddSearchResult()` - застосовує спеціальний клас для прямих URL

2. **VetaleSearchResultsPage.axaml**
   - Стиль `Border.result-item-direct` - спеціальна стилізація

3. **NavigationBar.axaml.cs**
   - Метод `TryNormalizeUserUrl()` - публічний метод для перевірки URL
   - Метод `ValidateAndNormalizeUrl()` - валідація та нормалізація

### Логіка в коді:

```csharp
// У методі RenderUnifiedResults():
var query = _currentQuery ?? string.Empty;
if (!string.IsNullOrWhiteSpace(query) && NavigationBar.TryNormalizeUserUrl(query, out var directUrl))
{
    string displayUrl = BuildDisplayUrl(directUrl);
    string domain = ExtractDomain(directUrl);
    var direct = new SearchResult
    {
        Url = directUrl,
        DisplayUrl = displayUrl,
        Title = $"🌐 Перейти на {domain}",
        Description = $"Відкрити сайт: {directUrl}",
        SourceType = "DirectUrl"
    };
    AddSearchResult(direct);
}
```

## Приклади використання

### Сценарій 1: Пошук сайту
**Ввід:** `reddit.com`
**Результат:** 
- Перший результат: "🌐 Перейти на reddit.com" з прямим посиланням
- Далі: результати з Wikipedia про Reddit

### Сценарій 2: Пошук конкретної сторінки
**Ввід:** `github.com/torvalds/linux`
**Результат:**
- Перший результат: "🌐 Перейти на github.com" з посиланням на github.com/torvalds/linux
- Далі: результати з Wikipedia/WebArchive

### Сценарій 3: Звичайний пошук
**Ввід:** `linux kernel development`
**Результат:**
- Немає прямого URL результату
- Тільки результати з Wikipedia, WebArchive та інших джерел

## Переваги

✅ **Швидкість** - миттєвий доступ до сайту без прокрутки результатів
✅ **Інтуїтивність** - зрозуміло, що це прямий перехід завдяки іконці та стилю
✅ **Візуальне виділення** - спеціальний градієнтний стиль
✅ **Гнучкість** - працює з будь-якими URL форматами
✅ **Безпека** - автоматичне додавання HTTPS
